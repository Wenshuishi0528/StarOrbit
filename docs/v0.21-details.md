# v0.21 — GitHub 云图灰底

## 原因与边界

本机下载的 8192×4096 `clouds-alpha.png` 是 LA 图像：Alpha 保存增强后的云图强度，亮度通道另有模糊、提亮的着色。应用读取 Alpha 正确；问题是把上游视觉增强后的强度直接当成云遮罩。

Live Cloud Maps 的生成器将 IR108、Dust RGB、自然色图混合：红外经过阈值和 gamma 1.46，红外／沙尘混合再用 gamma 2.0 提亮，可见光补充分支使用 gamma 1.5。EUMETSAT 案例显示，Dust RGB 在无云区也会表现地表温度、低层水汽差异。因此浅灰不能直接解释为薄云，也不能断言所有浅灰都不存在真实云层。

## 本次处理

仅对已知 GitHub 图源进行连续显示映射：`v = alpha²; opacity = v × smoothstep(0.01, 0.08, v)`。它抵消主要暗部提升，最低强度归零，中间连续过渡，保留强云信号；阈值是显示参数，不是卫星云检测阈值。由于原图已混合多种信号，无法精确反演出原始辐射或逐像素真实云量。没有按海陆一刀切，也没有另加灰色薄云层。

映射在共有云遮罩取样函数中完成；普通云、体积云、地面云影、夜光遮蔽同步生效。原始 PNG/JPEG 与快照导出不变，已有缓存打开即应用，不需要重新下载。NASA SatCORPS 的云相位／光学厚度处理不经过这条曲线；以物理依据为优先时应使用该来源，相关显示本身仍是简化可视化。

## 验证

- 自动测试：PNG Alpha、JPEG 红通道、分辨率上限、图源隔离、曲线连续性和单调性通过。
- GPU：14 组标量输入与 CPU 结果误差小于 1e-6；普通云／体积云生产着色器编译无错误。
- 实际下载的 PNG 以 2048×1024 验证纹理进入生产着色器，在同一大西洋视角切换修正前后，弱灰遮罩减弱、主要云带仍保留。此项验证渲染行为，不等于与同一时次真实云分类产品逐像素比对。
- 不增加贴图、网络请求或渲染通道；独立 HTML 约 211 MB。
