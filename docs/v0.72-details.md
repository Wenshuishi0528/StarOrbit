# v0.72 — 数据下载与自动恢复

## 本次原因

本机记录显示 NASA 检查未完成，保留了 2026-10-20 的合格云图；这不能等同于“源端已经最新”。实际请求发现新日期文件存在，但部分没有通过既有全球／两极覆盖门限，并伴有间歇性 TLS 连接中断。此前下载器没有重试这一类 curl 错误，也没有保留候选失败的具体原因。

中国空间站轨道中继把上游错误统一变成 502；本机 Python 的默认 CA 配置还会触发证书验证失败。前端原来的 25 秒等待也可能早于后端 Python 请求加 curl 回退结束。随后浏览器直连可能因跨域限制失败，覆盖了最初的诊断。

## 浏览器稳定性

2026-10-29 13:22 的本机诊断与此前多次记录均显示 Codex 主进程在原生框架中触发 `EXC_BREAKPOINT / SIGTRAP`；最新一次紧接着载入星轨的单文件页面。记录不足以确认唯一根因，不能将修改星轨等同于修复 Codex 的二进制程序。

本机服务现在优先提供 `dist-local` 分离资源构建：入口由约 237 MB 缩小为约 126 KB，模型、贴图、音频和轨道按需请求。原来的 `http://127.0.0.1:8771/StarOrbit.html` 与同源存储不变，NASA 和轨道中继仍可用。`npm run build` 同时生成单文件版和本机轻量版；独立 HTML 仍用于原来的离线分发，未包含 `dist-local` 的旧便携目录仍使用单文件入口。不会修改 Codex 的安装文件或浏览器安全设置。

外部浏览器验证还发现 Safari 对计时器的调用对象有严格要求；自动恢复已使用安全的包装函数。WebGL 初始化失败会明确显示原因，不再一直显示加载动画。

## 修复与恢复规则

- NASA 与轨道共用有总时限、体积上限的 HTTPS 下载器。暂时性连接、超时和服务错误最多尝试三次。curl TLS 栈出错时可改用 Python 的 TLS 栈，并加载可用的 certifi CA；两条路径始终验证证书与主机名，重定向仍须使用 HTTPS。
- 轨道中继总预算 90 秒，前端等待 105 秒；已由中继完成重试的错误保留类型和原因，不再用浏览器跨域失败覆盖。成功数据仍经过原轨道解析、较旧版本检查与任务隔离。
- 同一次 NASA 检查中，分段传输中断后可利用临时文件中已完成的分段继续一次，避免从头下载；仍受同一总预算约束。
- NASA 的 Range 响应同时核对状态码、字节区间和长度。缺少文件的 404／410、覆盖不足和真正读取失败分别记录；未发布文件 15 分钟后重新检查，覆盖不合格的检查结果缓存 6 小时。
- 全程 NASA 网络下载受 16 分钟总预算约束；同一来源连续连接失败会提前停止，保留已有云图。不会为了显示更新成功降低覆盖率、伪造极区云层或把失败检查标成最新。
- 用户发起的更新遇到可恢复错误后，程序按 30 秒、2 分钟、10 分钟自动重试。连续失败后暂缓，重新联网可继续恢复；不进行无限紧密轮询。没有发起过更新的资源不会因此自动下载。
- 等待自动恢复期间，离线时不继续发请求，重新联网自动继续。最近 24 小时内已保存的待恢复检查可在重新打开页面后接续。手动检查替代排队重试，清理某类缓存会取消该类等待中的恢复。
- 检查成功即清除待重试状态；已有云图、轨道、历史选择与任务切换保持原保护规则。永久权限、数据格式、证书验证等失败不会通过降低安全或数据校验要求来“修复”。

资源卡片显示候选数量、未发布／覆盖不足／读取失败计数、具体连接原因以及下一次自动重试时间。公网数据源停机或未发布合格产品时，程序可以恢复连接与重试，但不能生成不存在的新数据。

## 验证

官网实测曾耗时约 57 秒才完整返回 625,383 字节，新的下载器随后完成了实际下载并通过原有 OEM 校验，共 2,521 个有效样本，覆盖 2026-10-28 至 2026-11-04 UTC。正式本机页面再次点击轨道更新后，原来的超时提示已变为“未发现更新／已是最新可用数据”，确认下载结果与现有轨道一致。

2026-10-29 的真实 NASA 检查成功下载了 2026-10-23 12:00 UTC 云图，全球有效反演覆盖率 99.834%；检查 6 个候选，5 个较新候选覆盖不足，没有尚未发布或最终读取失败的候选。传输中确实出现过连接中断，程序利用已下载分段续传完成。新云图已通过 SHA-256 核对并存入本机共享目录，旧的 10 月 20 日云图仍保留。Safari 中正式本机地址的资源面板已显示新云图，并用于当前画面；这与独立的故障注入测试分开验证。

新增传输重试、TLS 回退、字节区间、服务诊断和自动恢复回归；覆盖重复任务、断网／重连、重试次数上限、取消过期计时器、恢复成功后保留显示选择，以及 NASA 未发布文件与来源故障的区别。

完整 `npm test`、6 项 SATCORPS 科学数据测试、离线／本机轻量／网页构建检查通过。Safari 故障注入中，NASA 与轨道首次请求分别返回可恢复错误，均在 30 秒后的自动重试成功，未再次点击。最后增加的分段续传逻辑另行通过服务回归与上述真实 NASA 下载验证。本机运行文件核对与应用签名检查通过；没有将本次本机更新发布到 GitHub 或在线版。

## English

Resource updates now retain actionable failure diagnostics and recover transient failures with bounded retries. Both verified TLS paths retain certificate and hostname validation. The local orbit request budget fits within the frontend timeout; NASA distinguishes unpublished files, inadequate coverage and transfer failures. Requested updates retry after 30 seconds, 2 minutes and 10 minutes, pause after repeated failures, and resume on reconnection. Existing data and manual selections remain protected. Recovery does not manufacture missing source data or weaken validation.
