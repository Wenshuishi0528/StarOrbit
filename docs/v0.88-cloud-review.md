## 已发现并复核修复的问题

### 1. P2：启动恢复的旧响应覆盖新下载

- 原位置：`src/cloud-library.js:51–63`；当前修复位置：`src/cloud-library.js:51–65`。
- 触发：页面启动恢复正在等待 `history/status`，用户已经开始另一个时次的下载，此时旧的 ready/error/cancelled 状态才返回。
- 影响：旧响应把当前 `task` 从新任务的 running 改成旧任务的终态；`downloadPromise` 和 `jobs` 仍运行，但 `downloading=false`，取消按钮消失，`cancel()` 也不会发送停止请求。
- 修复前离线证据：新任务 `2026-10-23` running 被旧 `2026-10-22` ready 覆盖；`activePromise=true, jobs=1, cancelPosts=0`。
- 最小修复：恢复请求捕获任务代次，写入前确认没有新 download/cancel；下载进度、完成及异常回调也绑定代次。
- 当前状态：已实现 `taskGeneration`，旧恢复响应不能写新任务。已核查代码，并通过当前 JS 回归的慢恢复测试。

### 2. P2：重复取消的迟到响应取消后续新任务

- 原位置：`src/cloud-library.js:90–99`；当前修复位置：`src/cloud-library.js:93–109`。
- 触发：用户并发点击两次取消，第一次已确认完成后开始新日期下载，第二次取消请求的响应随后才到达。
- 影响：第二次取消读取动态 `this.task.date/hour`，把后续新任务匹配为自己的目标，并真的发送 `stop(newJob.id)`。
- 修复前离线证据：停止请求 ID 顺序为 `[旧ID, 旧ID, 新ID]`，新任务被改成 cancelled。
- 最小修复：取消请求单飞，开始时捕获 id/date/hour/generation；状态比较和后续写入始终限定该目标。
- 当前状态：已实现 `cancelPromise` 与目标快照及代次检查；重复调用返回同一 Promise，只有一个取消请求。已核查代码和当前 JS 回归。

### 3. P2：旧自动历史模式固定化时丢失时间窗和目标时间

- 原位置：`src/weather.js:59–64`，旧预设调用位于 `src/weather.js:466`。
- 当前修复位置：`src/weather.js:59–65`、`src/weather.js:467`、`src/scene-share.js:43`。
- 触发：旧设置为 history/auto，最近的合格缓存距模拟时间超过六小时；或载入旧预设时，当前模拟时间与预设目标时间不同。
- 影响：迁移将远超六小时的图固定成显式 ID，绕过原 `apply()` 的六小时时间窗；旧预设还可能按载入前时间选错图。
- 修复前离线证据：模拟时间 `2026-11-01`、唯一缓存 `2026-09-01`，迁移后仍固定该缓存，相差 1464 小时。
- 最小修复：自动历史迁移保留六小时窗口；规范化方法接收目标时间，预设/场景传入其保存的时间。
- 当前状态：已实现时间参数及窗口检查，预设和场景传目标时间；超窗转 builtin、近窗按目标时间选图的 JS 回归已通过。

### 4. P2：另一地址清理共享图库会删除进行中的科学字段

- 原位置：`scripts/cloud_history_service.py:84`，清理入口 `scripts/serve.py:51–54`。
- 当前修复位置：`scripts/cloud_history_service.py:84–86`。
- 触发：两个本机端口共用完成图库，B 正在下载；A 空闲并清理云图缓存。A 只检查自己的 history 状态。
- 影响：本批原先把 B 的 `.download-*` 临时目录放在共用 cache 内，A 的 `CloudService.clear()` 对 cache 执行 rmtree，连科学字段一起删除；B 仍显示 running，后续转换/保存失败。
- 修复前离线证据：两个独立 HistoryService 共用临时 cache，A `clear_allowed=True, cleared=True`，B `state=running` 但 `fields.nc` 已不存在。
- 最小修复：未完成转换的工作目录放在共享完成图库之外，保留完成文件共享。
- 当前状态：下载 scratch 已移回系统临时目录。`python3 -B tests/cloud-library.py` 五项通过，其中包括另一地址 clear 后 scratch 字节仍存在。

### 5. P2：后台通知后重开图库无法显示所选图预览

- 原位置：`src/cloud-history.js:17–18`；当前修复位置：`src/cloud-history.js:16–19`。
- 触发：关闭图库后，下载进度或 Weather 渲染通知再次调用图库 render；随后重开并选回同一图。
- 影响：关闭期间 preview 把 SHA 写进 `previewKey`，但没有生成图；重开时相同 SHA 被直接跳过，预览持续隐藏。
- 修复前离线证据：真实 mount/render/preview 代码加最小 DOM 夹具，首次 `hidden=false, decodes=1`；close→后台 notify→open 后 `hidden=true, decodes=1`。
- 最小修复：关闭的 dialog 在登记 previewKey 之前返回。
- 当前状态：已增加入口检查。独立脚本 `/tmp/starorbit-cloud88-ui-repro.mjs` 使用真实 CloudLibrary.subscribe/notify 重新执行该流程，现为 `hidden=false, decodes=2`，通过。
