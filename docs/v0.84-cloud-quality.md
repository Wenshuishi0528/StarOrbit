# v0.84 云图质量检查与回退

## 诊断与数据来源

- GitHub Live Cloud Maps 的上游说明承认图像质量/新鲜度不能保证、存在缺测孔洞，极区用镜像填补。该成品是增强过的卫星可视化图，包含地表信号，不能从合成灰度可靠反演实际云量。原有 gamma 与局部模糊不能修复大陆尺度误识别，因此暂停该来源的下载和应用，保留旧档的预览、导出、手动删除。
  - https://github.com/matteason/live-cloud-maps
- NASA SATCORPS GCC 是多颗 GEO/LEO 卫星的云属性拼接产品，并非无缝的自然照片。官方说明夜间厚云的光学属性使用机器学习方法估计。
  - https://satcorps.larc.nasa.gov/new/products/global-cloud-composite/
- 本机 `20261020T1200-v2a.png` 与 `20261023T1200-v2a.png` 都有大面积均一灰度多边形。固定 1024×512 最近邻样本中，灰度206平台分别占全图0.6363%与1.4202%，占亮平台98.67%与98.99%。两代均拒绝，不能把上一代自动称为可靠。
- 10/23 原始 NetCDF 抽样（网格 y400/x9500，约78.9°N/83.9°E）8×8 块：phase=1（水云）、packed COD=3200，即光学厚度32，转换后灰度206；sensor241=Metop-B，太阳天顶角约97.9–98.0°，relative_time约−3682秒。均一值已存在源字段，非本地把填充值涂白。此证据不足以断言上游算法生成固定值的具体原因。
- 用户给出的23.24°N/179.59°E在这两份本机原图附近是接近0的透明值，日期线检测最长直线突变仅1个样本；未复现该位置所述长缝，不据此修改正确的经度环绕。其他日期、云图平移和不同显示模式仍可能表现不同。

## 检查与保留规则

1. 原数据仍核验时间、全球/极区有效覆盖、SHA-256及网格；新增 packed optical depth 的 valid_range 检查，越界值不作为有效云反演。
2. 图像采用1024×512源像素中心最近邻抽样。高灰度≥180、3×3邻域范围≤2的平坦区域，若某个灰度占全图≥0.5%且占全部亮平台≥60%，隔离为异常平台。日期线及内部阶跃需满足同号幅度≥64、两侧局部变化≤12，且连续长度分别达到32（日期线）、64（纵向）、128（横向）个样本。
3. 这是保守的显示伪影筛查，**不是气象真实性验证**。真实厚云也可能触发拒绝；斜线、曲线接缝、渐变异常不保证检出。不会删除云、局部重绘、复制其他日期天气或以模糊掩盖问题。
4. 候选先检查再入库；失败继续使用已通过检查的版本。无合格下载时明确使用内置静态图。源质量拒绝不进入网络失败的快速重试；同候选拒绝记录暂存6小时，成功检查沿用15分钟缓存，真实网络失败仍有限重试。
5. 质量报告有schema版本并绑定数据身份；旧磁盘档案、旧浏览器缓存和导入快照均检查，不能靠历史选择或同文件缓存路径绕过。原档不因检查失败而被直接删除；手动清理仍受用户控制。
6. 自动清理保护最近两代通过检查的云图，超过预算时提示保留。没有持续后台扫描或逐渲染帧检测；真实8K文件在本机单次Python检查约0.4秒。

## 验证

- Python/JS检测对真实10/20、10/23两帧的指标和拒绝原因一致；合成回归包含自然结构厚云、平台、日期线/内部长缝、短云边界、不可变输入、原数据范围。
- 资源回归覆盖坏新图不能覆盖好旧图、同坏候选避免重复下载、重启回退、导入不信任声明、自恢复网络错误、旧缓存迁移与配额保护。
- 独立subagent分别核对源数据、客户端保留链路和最终改动。未将这次本地修复自动发布到GitHub或线上。
