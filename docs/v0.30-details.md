# v0.30 · 模块化航天器与公共资源

软件现在通过界面导入航天器配置、模型和轨道。地球、云图、极光、星空、时间与操作系统由一个公共环境实例提供。

## NASA 云图恢复

旧服务重启时将状态初始化为 idle，没有载入磁盘 PNG/JSON；网页也只在清理一份历史退役图片时检查服务器结果。更新期间，图片接口又只接受 ready 状态。这三处共同造成已有云图在页面中不可用。

本版将已验证图片与下载进度分别保存。服务启动从公共目录恢复 SHA-256 一致的完整图片；running/error 状态仍提供上次成功图片。网页普通启动读取资源，正在下载时接续查询；旧图读取失败仍继续接管更新。图片请求携带 SHA-256 标识以匹配元数据。用户原来选择的图源继续生效。

公共目录：`~/Library/Application Support/Tiangong Orbit Simulator/clouds`。旧临时目录中的有效图片自动复制到这里。清理公共云图后，迁移标记避免旧图再次导入。`TIANGONG_CLOUD_CACHE` 可为独立测试指定其他目录。

## 界面导入

点击任务选择框下的“下载配置模板”，编辑后点击“导入航天器”，一次选择配置、模型和轨道。配置示例：

```json
{
  "format": "tiangong-mission-1",
  "id": "my-satellite",
  "name": "我的卫星",
  "planet": "地球",
  "category": "卫星",
  "center": "EARTH",
  "model": {
    "file": "model.glb",
    "metresPerUnit": 1,
    "forwardAxis": "+Y",
    "normalAxis": "-Z"
  },
  "orbit": { "file": "orbit.json" },
  "spinRpm": 0
}
```

- `id`：每个任务唯一，2–63 位小写字母、数字、连字符，以字母开头。
- `name/category/planet`：组成“星球：类别：名称”。当前轨道引擎处理地球。
- `model.file`：独立 GLB 2.0 文件，网格和纹理包含在文件内，大小上限 128 MB。
- `metresPerUnit`：原模型一单位对应的米数；米制为 1，毫米制为 0.001。
- `forwardAxis`：原 GLB 的头部轴向，映射到星体 +Z；航向跟随时沿轨道速度。
- `normalAxis`：原 GLB 中期望朝轨道法向的轴，映射到星体 +Y。两轴取 ±X/±Y/±Z 且互相垂直，软件生成右手坐标变换。
- `orbit.file`：轨道文件名，大小上限 30 MB；OEM、位置速度 JSON 使用地心 EME2000/UTC，距离 km、速度 km/s。设为 null 时进入模型查看。
- GP/OMM JSON：在 orbit 中填写 `noradId` 与 `objectId`；`updateSource: "celestrak"` 启用对应编号的在线更新。传播采用 SGP4，展示窗口为历元前后各三天。
- `spinRpm`：星体 +Z 右手自旋速度，0 关闭该控件；`spinSource` 可填写资料网页。`axes` 可提供模型轴向说明。

导入先校验配置、GLB、轨道和模型尺寸，再保存并切换任务。相机距离按尺寸生成，全部模型使用同一套拖动逻辑。导入任务与初始轨道保存在当前浏览器数据库，下次打开自动注册。恢复默认设置清除任务选择、轨道选择与环境设置，导入模型库继续保留。

## 状态边界

| 公共部分 | 任务部分 |
| --- | --- |
| 地球、云图、极光、星空、画质、时间 | 模型、轨道及在线更新编号 |
| 资源下载、NASA 磁盘库、环境缓存 | 姿态、自旋、镜头记忆 |
| 鼠标交互、姿态面板、渲染流程 | 模型轴向、比例和功能配置 |

内置清单位于 `assets/missions/catalog.json`。`MissionLibrary` 管理导入包；`OrbitRepository` 管理每个任务的轨道选择和更新；`Weather` 管理公共云图/极光及数据面板。旧轨道选择自动迁移到独立键，场景和收藏继续兼容。

普通任务切换保留公共环境。导入/恢复完整场景及环境收藏时，按其保存的环境设置恢复。缺少有效轨道时显示模型，界面的轨道状态提供跳转到有效时段的入口；公共环境资源继续保留。

## 验证

自动验证覆盖全量既有测试、24 种轴向映射、任意 NORAD 更新地址、轨道读取竞态、NASA 重启/更新/失败恢复、清理后的状态、损坏资源校验和导入失败回滚。浏览器验证使用实际东方红 GLB 接入两个新任务（原比例的 100 倍与 0.00001 倍），检查相机、头部方向、刷新、场景往返和公共 NASA 纹理复用。原有 60 项任务/姿态/鼠标/离线回归继续通过。

两位 subagent 分别审查公共资源和导入流程。审查发现的固定相机距离、导入并发锁、小尺寸相机阈值、重置键和下载接管中断问题均已修复。验证记录见 `v0.30-validation.json`。
