# v0.92 Safari 启动修复

## 实际复现

桌面启动器打开 `http://127.0.0.1:8771/StarOrbit.html`，用户实际使用 Safari。先前内置浏览器拥有另一套浏览器缓存和场景设置，启动成功不能覆盖用户所选的 NASA 云图恢复路径。

经用户授权，在 Safari 原有缓存、8K 画质、五舱中国空间站场景下复现。启动状态停留在 Weather / mission restore 与 Cloud image decode；地球贴图请求于 14:44:34 完成，直到 14:45:47 天气恢复之后的图库请求才发出。页面最终显示所选 NASA 2026-11-04 04:00 UTC 云图，有效覆盖 76.19%。这是含有效性 alpha 的云图路径，小地图当时尚未绘制。

## 修复

- 原有效性云图处理对 4096 行逐行调用 drawImage/getImageData，在 Safari 上产生大量同步读回。改为 64 行一批，最多 2 MiB 临时读回数据，检查过期请求并逐批让出主线程，保持逐像素输出不变。原始 PNG 和缓存未删除、未修改。
- Weather.ready 保留缓存、轨道与选择恢复，不再等待云图/极光纹理解码。Environment 首次准备画质时也不再提前解码云图；用户后续切换画质仍重新应用云图。
- 主界面恢复保存时间和画质、完成首帧后才启动后台纹理恢复，复用现有 token 与 pendingApply 机制，成功后再更新当前使用状态。
- 加载页显示真实阶段，控制台记录毫秒时间。小地图底图、平滑夜区、轨迹描边及定位功能全部保留，浅色晨昏边界线仍不绘制。

## 验证

- 仅改条带读回后，在同一 Safari、缓存、NASA 图和 8K 设置下，日志显示云图处理开始于 3287 ms，完成于 5419 ms，首帧于 5433 ms。未通过切换到内置云图或降低画质绕过故障。
- 自动测试真实 Weather.restore 在纹理 Promise 不返回时仍可完成；后台恢复只启动一次。逐像素核对有效性 alpha、条带边界，验证读取次数与中途取消。
- 完整 npm test、离线/本机/网页构建通过。最终 v0.92 在用户 Safari 原配置下首帧为 3533 ms；其后显示原 NASA 2026-11-04 04:00 UTC、76.19% 有效覆盖云图，未清理缓存或降低画质。
- [独立审查](v0.92-startup-review.md) 无未解决 P1/P2，并补查处理过程中切换云图、非整条带高度及有效性像素保持。
- 桌面启动器检查返回 READY，代码签名验证通过；访达启动触发 macOS 重新确认文稿访问权限。系统日志明确为应用签名变化后既有 code requirement 不匹配、等待授权。这与页面内云图解码阻塞是两项不同问题；系统授权窗口不能由当前自动操作工具处理，需要用户确认。
- 用户手动允许文稿访问后，已核对桌面启动器打开的 Safari 页面：v0.92 主界面正常、加载层消失，保留五舱空间站、8K 画质、原 NASA 云图与全部小地图显示，时间及位置读数持续更新。桌面启动验证完成。
