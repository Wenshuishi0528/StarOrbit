# v0.91 小地图功能与资源边界独立审查

结论：未发现 P1/P2。除用户要求去掉的浅色晨昏边界外，明亮独立底图、平滑昼夜、轨迹暗描边、昼夜图例及原定位交互均已补齐；没有把本轮扩展成启动或主场景画质改造。

## 功能与回归

- `src/minimap-lighting.js:5–7,28–35` 保留原 v0.89 的 0° 至 -6° 夜侧平滑公式，白天不压暗、深夜上限 0.72。独立对比原实现：8 组方向在 360×180 分辨率下输出逐字节一致，包括分日方向、南北两极方向及南北偏角。
- `src/minimap.js:63–77` 恢复 4px 暗描边和 1.7px 青／金轨迹；日期线分段、白色当前位置及原点选／拖动／键盘逻辑保留。没有恢复 `drawTerminator`、`terminatorSegments`、浅色曲线或对应图例。
- `src/minimap.js:79–87` 只在首次实际画夜区时创建辅助 canvas、raster 和 ImageData；ImageData 共用 raster 的 pixels，不复制大数组。窗口变化只缩放显示，不重新分配遮罩。
- 独立底图 `assets/earth/simple/day.jpg` 实测 90,514 字节，低于用户约 1MB 的示意地图需求；文件大小与浏览器解码、画布驻留内存分别计算。

## 资源与启动边界

- 遮罩固定 360×180。pixels 为 259,200 字节，连同经纬三角表和横向工作数组，四个 TypedArray 合计 270,720 字节（约 0.258 MiB）；不随主画质、DPR 或窗口尺寸扩大。
- 太阳方向按上次实际计算值缓存，单分量变化不足 1e-4 时跳过重算和上传。独立近方向检查的最大 alpha 差为 1/255；2000 次方向更新后四个 TypedArray 仍是原对象。缓存没有按时间或画面累积条目。
- 普通 250ms／拖动 33ms 的既有节流保留。当前本机 Node 200 次遮罩计算中位约 0.15ms、P95 约 0.59ms，属于纯计算结果，不代表浏览器整页帧率。
- 模块顶层没有大数组生成、异步启动任务或主场景资源载入；raster 构造保持惰性。`app.js`、`environment.js`、`environment-math.js`、`weather-cache.js`、`session-memory.js`、`runtime-assets.js` 与 `/tmp/starorbit-startup90-baseline` 对应文件完全一致，没有新增启动 guard、像素预算或加载器变化。
