# v0.90 · 启动回退与小地图简化

> **版本专题／历史证据**：本文保留历版设计与当时检查，部分章节含后续补充。现行功能与操作见[使用手册](../使用说明.md)，验证范围见[验证指南](verification.md)。文中的旧版本结果不代表当前版本重新验收；标为源码的链接需联网查看对应提交。

用户反馈 v0.89 交付后卡在“正在准备星轨”，甚至导致整机卡顿。原来的验证覆盖内置浏览器、构建和文件同步，却没有覆盖用户的实际启动条件；构建通过不能替代启动验证。

按照用户要求，本次撤回 v0.89 新增的逐像素离屏画布、晨昏线曲线描边和轨迹新增描边，删除相关实现及专属测试，恢复 v0.88 的小地图绘制路径。对照修改前保存的实际源码，核心绘制文件现在仅有三处差异：

1. 显式读取独立的原版 1K 显示底图，保留旧资源回退。
2. 移除全图压暗。
3. 夜区遮罩最大不透明度由 0.60 改为 0.72。

图例保留“白天／夜晚”，浅色边界线及其图例均移除。不调整主场景画质、地表、云图选择或持久化数据，不将未经证实的启动推断扩展为性能重构。

## 诊断边界

内置浏览器的 v0.89 8K 空间站重开约 2.6 秒进入模拟器，未重现用户的整机卡死。此前在默认浏览器看到加载停留，但用户已关闭页面并要求仅在内置浏览器检查，没有获得原始故障现场的完整错误或性能记录。因此不能把卡死确定归因于 8K、大气表计算或某一个新函数。

独立复核没有发现环境／天气就绪 Promise 的循环依赖；大气表本机 Node 同步计算约 0.33–0.36 秒，不能据此解释长期卡死。修复采取撤回本批新增渲染路径的保守方式，不把排查中的推测写成已确认根因。

## 验证

- 完整 `npm test` 通过，离线 HTML、本机和 web 三种构建通过。
- 内置浏览器在生产启动地址重新载入 v0.90，约 3 秒进入主界面；另关闭测试页、创建新页面重新打开，8K 空间站进入主界面，`body[data-ready=true]` 且加载层隐藏。
- 真实截图确认浅色边界线及对应图例消失，昼夜对比保留；浏览器无 warn/error。测试后已恢复测试前的任务、画质和视窗尺寸。
- 桌面运行目录与源码构建的关键文件哈希一致，应用签名核验和启动器 `--check` 通过（该检查不打开外部浏览器）。
- [独立回退审查](v0.90-minimap-review.md) 确认核心绘制文件严格等于 v0.88 加上述三处差异，无新绘制实现或删除后的死引用。

原始外部浏览器整机卡死未在内置浏览器复现；这里不将回退后的内置浏览器通过冒充原始故障根因已获证实。
